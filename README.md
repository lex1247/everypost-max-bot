# EveryPost: Telegram → Telegram и MAX

Управление репостингом и собственными публикациями через @EveryPost_bot. Новый сервис работает отдельно от исходного MAX-бота. Интеграция ВК отложена.

## Управление

Быстрые команды совпадают с MAX по названиям, описаниям и порядку: `/menu` — главное меню, `/newpost` — создать пост, `/inbox` — предложки, `/drafts` — черновики, `/scheduled` — отложенные, `/published` — опубликованные и автоудаление, `/channels` — мои каналы, `/cancel` — отмена ввода, `/help` — помощь. Разделы открываются сразу из списка команд Telegram, затем выбирается доступный канал. `/new` и `/posting` также работают как сокращения. При незавершённом вводе переход не сбрасывает правку; `/help` показывает справку, `/cancel` отменяет ввод без изменения сохранённых постов и расписания. Пересланное сообщение или подпись к фото со строкой команды остаются материалом поста.

«Добавить назначение» подключает канал Telegram или MAX. «Добавить источник» принимает ссылку на открытый Telegram-канал. «Связать» задаёт маршруты. «Режим публикации» выбирает исходный текст или переписывание с ИИ отдельно для каждой связки. Фото сохраняются; служебная ссылка на источник не добавляется.

«Постинг» открывает:

- Создание собственного поста с текстом, фото, видео или альбомом.
- Предпросмотр, редактирование текста с сохранением медиа, замену материала.
- Черновики, предложку с персональной ссылкой канала, рассмотрение предложений.
- Календарь отложенных публикаций, перенос и отмену расписания.
- Подпись, URL-кнопки, кнопку предложки и ссылку обсуждения.
- Отдельную, явно включаемую копию в группу обсуждения.
- Администраторов с доступом к конкретному каналу. Настройки канала и состав администраторов меняет владелец. Для Telegram также проверяются права пользователя в самом канале; для MAX доступ из Telegram выдаёт владелец нового бота.
- Список опубликованных собственных постов и календарь автоудаления.

Собственные публикации и предложка не переписываются автоматически. Режим ИИ относится к репостам из подключённых источников. Переписывание проверяет сохранность имён, чисел, ссылок и смысла; неудачный результат сохраняется для проверки. Ожидание нейросети не блокирует очередь собственных постов.

## Ограничения медиа и расписания

Для ручных постов Telegram допускает до 10 вложений, 1024 символов подписи к медиа или 4096 символов без медиа. Для MAX: до 12 вложений (до 11 с кнопками), до 4000 символов. Подпись канала входит в лимит. Слишком длинный ручной пост остаётся в черновике до исправления.

Telegram не позволяет передать кнопки в `sendMediaGroup`: у альбома с кнопками текст и кнопки выходят отдельным сообщением сразу под альбомом. Одиночное фото или видео получает кнопки под подписью. Порядок фото и видео в альбоме сохраняется.

Видео для переноса из Telegram в MAX: MP4, не больше 20 МБ (ограничение скачивания Telegram Bot API). Репостинг из публичного веб-превью Telegram переносит фотографии; видеопосты из такого источника сохраняются для проверки, поскольку веб-превью не всегда предоставляет доступ к самому видео.

Автоудаление включается явно для отдельного поста. В Telegram выбирается срок до 47 часов после публикации, с запасом относительно ограничения платформы 48 часов. Удаляется только публикация в канале, включая её части; копия в обсуждении остаётся. Неопределённый ответ площадки требует проверки, не считается успешным удалением.

Оформление и параметры копии в группу сохраняются вместе с черновиком. Изменение общих настроек не переделывает уже сохранённые посты. При отзыве администратора его отложенные посты переходят в проверку; права повторно проверяются непосредственно перед отправкой.

## Запуск

Python 3.11+, Linux/macOS. Установить `requirements.txt`, заполнить `.env` по `.env.example`, выполнить `python app.py`. Локальный запуск использует SQLite и получение команд Telegram через long polling. Одновременно разрешён один процесс.

Для открытых Telegram-источников аккаунт чтения не нужен. Дополнительный вход через `login.py` требуется только для отдельно настроенного чтения через аккаунт. Не загружайте `.env`, базу, токены или файлы сессии в GitHub.

## Render Free и переход на платный тариф

[Инструкция размещения](RENDER.md). `render.yaml` создаёт **один новый бесплатный web service** и использует существующую базу `everypost-db`. Он не изменяет конфигурацию MAX-сервиса. Таблицы нового сервиса находятся в схеме PostgreSQL `repost_bot`; таблицы MAX в `public` не затрагиваются.

Free засыпает после 15 минут без входящих запросов. Пока сервер спит, опрос источников и расписание не выполняются. Сообщение боту будит сервер. Просроченная более чем на 5 минут отложка сохраняется для проверки, а не выходит с большим опозданием. Бесплатная PostgreSQL действует 30 дней с момента создания, поэтому её нужно своевременно перевести на платный тариф или перенести.

Переход на платную вычислительную мощность web service убирает засыпание; отдельно переводится сама база. Перенастраивать источники и каналы не требуется. Платный тариф рабочего пространства сам по себе не меняет тип экземпляров.

## Проверки и восстановление

`python -m unittest discover -p 'test_*.py' -q` проверяет маршруты, ИИ, права, медиа, предложку, транзакции, повторы, календарь и удаление. Сборка Render дополнительно запускает `postgres_selftest.py` на одноразовой локальной базе, до подключения к рабочей базе и активации бота.

После неопределённой отправки проверь канал и используй `/errors`. `/resolve ID sent` отмечает вышедший пост, `/resolve ID retry` повторяет только неподтверждённые части; повтор уже вышедшей части создаст дубль. `/pause` приостанавливает репостинг, собственные отправки и автоматическое удаление; `/resume` продолжает. Сбор источников продолжается во время паузы, если сервер не спит.

Перезапуск во время отправки не вызывает автоматического повтора. В PostgreSQL один активный обработчик защищён блокировкой на соединении; новая версия может принимать webhook в сохранённую очередь, пока старая завершает работу. Журнал команд содержит только события Telegram и безопасные ошибки; токены в него не записываются.
